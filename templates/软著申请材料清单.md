# 软著申请材料清单（实战版）

> 沉淀自 Drop2Markdown 软著申请实践（Mac 桌面版 / Windows 版 / Web 版 3 件策略）

## 一、申请策略

### 申请几件？

| 产品形态 | 建议 | 理由 |
|---|---|---|
| 单一形态（只有 App 或只有网站） | 1 件 | 一一对应 |
| 多端产品（桌面+Web+插件） | **按平台分申** | 共享引擎但平台壳代码不同，实务上属独立作品；分开申请 = 多件证书，维权举证更清晰 |
| 共享核心引擎的多端 | 核心引擎代码各件均可包含 | 审查不查重，各端「表现层」代码差异是关键 |

### 申请人主体

- **个人申请**：身份证即可，无费用门槛（官方通道，各地版权中心流程略有差异）
- **公司申请**：营业执照副本；若计划以公司运营商业化产品，建议以公司名义申请
- 个人 vs 公司：软著可后补变更（转让/变更著作权人），初创期个人申请完全可行

## 二、材料清单（每件申请）

- [ ] **源程序前 30 页 + 后 30 页**（共 60 页）
  - 每页不少于 50 行（最后一页可不满），A4 纵向
  - 页眉标注软件名称+版本号，与申请表完全一致
  - 不足 60 页全量提交
  - ⚠️ 提交前用 `wc -l` 核对页数行数；含中文注释的源码直接排版即可
- [ ] **操作说明书/用户手册**（配合 `操作说明书骨架.md` 使用）
  - 图文并茂：界面截图 + 操作步骤，一般 10-20 页
  - 覆盖主要功能模块，每个功能至少一张截图
- [ ] **申请表**（中国版权保护中心官网在线填写生成）
  - 软件全称：建议「产品名 + 功能描述 + 软件」结构，如「Drop2Markdown文档转换软件」
  - 版本号：与材料中出现的所有版本号严格一致（⚠️ v1.3.3 教训：8 处版本号必须全对齐，含 manifest.json / version.json / 说明书页眉）
  - 开发完成日期：以 git tag 或首次构建日期为准，**留好 git 提交记录作为时间证据**
  - 首次发表日期：未公开发表可不填

## 三、流程与耗时（官方个人通道）

1. 中国版权保护中心官网（ccopyright.com.cn）注册 → 在线填报
2. 上传材料 → 等待受理（约 1-2 个月）→ 审查（约 1-2 个月）→ 发证
3. 常规排队全程约 **2-4 个月**；加急代理可压缩到 1 个月左右（代理费另计，非必需）
4. 官方不收登记费（2017 年起停征）；如走代理服务费约 ¥300-800/件

## 四、时间线证据（申请前就该做）

软著审查不严但**维权时看时间线**，git 是最便宜的权威证据：

- [ ] 源码推 GitHub **私有仓库**（提交记录 + tag 不可篡改，时间权威）
- [ ] 每次发版：zip 归档 + `git log` 快照 + 关键文档快照
- [ ] 可选增强：可信时间戳（tsacn.org）固化源码包哈希；重要节点公证

## 五、常见驳回点与规避

| 驳回点 | 规避 |
|---|---|
| 材料中版本号不一致 | 提交前全局 grep 版本号核对（含 JSON manifest） |
| 说明书截图与实际界面不符 | 用当前版本重新截图，勿用旧版截图 |
| 源代码每页行数不足 | 重新排版，保证 ≥50 行/页 |
| 软件名称含违规词 | 避免「中国/国家/最佳」等词汇；不含他人商标 |
| 表格填写与材料矛盾 | 申请表「开发完成日期」不得晚于说明书所示功能上线时间 |
