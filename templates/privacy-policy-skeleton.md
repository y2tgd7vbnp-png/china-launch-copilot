# 隐私政策骨架（PIPL 合规版）

> 适配桌面 App / Web /浏览器插件三种形态，按需删减

## 写作原则

- **写了就要做到**：政策里的每句话都是承诺，PIPL 下虚假承诺有行政处罚风险
- 纯本地处理的产品，最大的卖点是「不收集」，那就明明白白写清楚收集了什么、没收集什么
- 政策页必须**可公开访问**（URL 挂到商店/应用内）

## 骨架结构

```markdown
# XX 隐私政策
生效日期：YYYY-MM-DD | 版本：v1.0

## 1. 引言
   我们（产品名，开发者名称）重视你的隐私。本政策说明我们如何处理你的信息。
   【一句话定调：本应用所有转换均在你的设备本地完成，我们不上传、不收集你的文档内容。】

## 2. 我们收集哪些信息
   ### 2.1 我们不收集的（本地处理产品重点章节）
   - 你的文档/文件内容 —— 全程本地处理，不离开你的设备
   - 任何个人身份信息（姓名、邮箱、联系方式）
   
   ### 2.2 我们可能处理的（按实际情况删减）
   - 本地使用统计（仅存于你的设备，如 stats.jsonl，你可随时删除）
   - 崩溃/错误信息（如发送诊断，写明发送什么、去哪）
   - 网络服务组件（如版本检查/在线转换，写明传输内容与目的）★有则必写

## 3. 第三方服务
   列表：服务名 | 用途 | 处理的数据 | 隐私政策链接
   （无第三方服务就写「本应用不使用任何第三方分析/统计/广告服务」）

## 4. 信息存储与安全
   - 本地存储位置、保留期限（用户可删除）
   - 技术措施（如 MCP 白名单、输入大小限制）

## 5. 你的权利
   查询/复制/更正/删除/撤回同意的方式（本地产品即：删除应用数据即可）

## 6. 未成年人
   本应用不面向未成年人，不 knowingly 收集未成年人信息。

## 7. 政策更新
   重大变更将通过应用内提示/网站公告通知。

## 8. 联系方式
   开发者邮箱（建议专用邮箱，如 xxx@foxmail.com）
```

## 分形态差异要点

| 形态 | 必须写清 |
|---|---|
| 桌面 App | 文件访问权限范围（如仅「文档文件夹」）、本地日志位置 |
| Web | 浏览器本地处理 vs 服务器处理的边界；Cookie/LocalStorage 用途 |
| 浏览器插件 | manifest 每项权限的用途（对应商店隐私问卷）；是否读取浏览历史（否要明说） |

## 常见坑

1. 声称「不收集任何数据」但埋了统计 SDK → 虚假陈述，商店下架+行政风险
2. 插件申请 `<all_urls>` 权限但政策不说用途 → 商店拒审
3. 政策写「收集崩溃日志」却没给关闭方式 → 争议条款
4. 邮箱用失效邮箱 → 用户/监管联系不上，视为不合规
